# ハビタマ Androidアプリ 開発仕様書 v0.5

- 更新日: 2026-08-11
- アプリ版: 0.6.0（versionCode 8）

## 1. 今回の変更

初回設定と行動編集で、カテゴリ別サンプル、単位選択、達成方法を利用できるようにする。設定画面ではブラウザやGitHubの画面を経由せず、最新版の確認、APKダウンロード、検証、Androidインストーラー起動までを行える。

### 初回設定契約

- サンプルは初期状態で未選択とし、利用者が必要なものだけ選択する。
- サンプルを「おすすめ・運動・健康・学び・暮らし・お金」で絞り込み、名前・目標値・単位・育つ力・達成方法をまとめて入力できる。
- サンプルには歩数、筋トレ、ストレッチ、睡眠、水分、間食カロリー、勉強時間、単語、読書、片づけ、瞑想、日記、貯金、支出上限を含める。
- 「自分で行動を作る」から、タイトル、正の整数の目標値、単位、育つ力を入力できる。
- 単位は回、分、時間、歩、個、ページ、kcal、g、kg、ml、L、杯、円、日から選択でき、10文字以内の自由入力も許可する。
- サンプルと自作行動を合わせて最大3件とする。
- 作成済みの自作行動は開始前に削除できる。
- 1件以上を選択または作成した場合だけ「これで始める」を有効にする。
- 設定・戻るボタンを含む上部ヘッダーはステータスバーの内側へ重ねず、48dp以上の操作領域を確保する。

### システムバー表示契約

- アプリ背景は明色のため、ステータスバーの時計・通信・電池アイコンを濃色表示に固定する。
- ナビゲーションバーのシステムアイコンも濃色表示に揃える。

### 目標変更契約

- 既存目標の変更は「今すぐ変更する」の保存完了直後から有効にする。
- 過去日の記録スナップショットは変更しない。
- 今日すでに記録がある場合は、同一トランザクションで今日の記録を新しい目標版へ移し、レコード数を増やさない。
- 育つ力を変更した場合は、今日獲得済みのポイント分類を旧タイプから新タイプへ移す。累積ポイント合計は変えない。
- 今日の実績を再入力した場合は、新しい目標値で再評価し、差分だけを累積ポイントへ反映する。
- v0.4.1以前に翌日適用として予約済みの変更は維持する。新たな変更を保存した場合は、その予約を置き換えて即時反映する。

### 達成方法とデータ契約

- `GoalEntity`は`evaluationMode`を保持し、`AT_LEAST`または`AT_MOST`のみを許可する。
- 既存目標はRoom migration 2→3で`AT_LEAST`として維持する。
- 日次記録は`evaluationModeSnapshot`を保持し、目標変更後も過去の評価方法を変えない。
- `AT_LEAST`は従来式を維持し、実績÷目標を達成率、超過ボーナスを評価1.2までとする。
- `AT_MOST`は実績が目標以下なら達成率100%、評価1.0、10ポイントとする。目標を超えた場合は目標÷実績を達成率と評価値に使用し、超過ボーナスは付けない。
- 報告画面では`AT_LEAST`を「目標以上」、`AT_MOST`を「目標以内」と明示する。

### 端末カレンダー読み取り契約

- Android `CalendarContract`のCalendar Providerを使用し、端末に同期済みで表示状態のカレンダーを対象とする。
- 要求する権限は`READ_CALENDAR`のみとし、`WRITE_CALENDAR`はmanifestへ追加しない。
- 初期状態は無効とし、設定の「端末カレンダーの予定」を利用者がオンにした時だけ権限を要求する。
- 初回許可時は表示可能なカレンダーを選択状態とし、設定画面でカレンダー単位に表示・非表示を変更できる。
- 繰り返し予定を展開できる`CalendarContract.Instances`を使用し、現在月の範囲だけを問い合わせる。
- 月表示ではHabitama記録を緑系、外部予定をカレンダー色のマーカーで区別する。
- 日付選択時は終日または開始・終了時刻とタイトルを表示し、予定選択時はAndroid標準の予定表示画面を開く。
- 予定、アカウント名、カレンダー名はRoomへ保存しない。SharedPreferencesには有効状態と選択したカレンダーIDだけを保存する。
- 権限拒否、同期カレンダーなし、取得失敗でもHabitamaの記録カレンダーは継続して使用できる。

## 2. 更新情報契約

- 更新情報は`https://github.com/toshiwd/Habitama/releases/latest/download/version.json`からHTTPSで取得する。
- キャッシュを使用せず、接続15秒・読取20秒でタイムアウトする。
- `versionCode`がインストール済みアプリより大きい場合だけ更新可能とする。
- `version`、`versionCode`、`apkUrl`、`sha256`を必須とし、`releaseNotes`は省略可能とする。
- APK URLはHTTPSの`github.com`に限定する。
- 通信失敗、タイムアウト、不正JSONは日本語で表示し、再確認できるようにする。

## 3. APKダウンロード契約

- Android標準の`DownloadManager`を使用し、ブラウザへAPK URLを渡さない。
- ダウンロードはアプリ固有の外部Downloads領域へ保存し、ストレージ権限を要求しない。
- システム通知にも進捗・完了を表示し、設定画面を閉じても継続する。
- 待機、進行率、一時停止、失敗、検証完了を設定画面へ表示する。
- 失敗時は同じ画面から再ダウンロードできる。
- 新しいダウンロードを開始する際は、Habitamaが以前登録した更新ダウンロードだけを削除する。

## 4. 安全性とインストール契約

- ダウンロード完了後、APK全体のSHA-256を計算して`version.json`と照合する。
- 不一致・読取失敗時はインストールボタンを表示しない。
- 検証成功後だけAndroid標準のパッケージインストーラーへcontent URIを渡す。
- Android 8以降で提供元許可がない場合は、Habitama専用の「不明なアプリのインストール」設定を開く。
- 署名鍵は従来のHabitamaリリース鍵を維持し、公開前に直前版と証明書SHA-256を照合する。

## 5. 受入条件

- 公開`version.json`をアプリから取得・解析できる。
- 旧versionCodeのビルドでは更新版とダウンロードボタンが表示される。
- 公開APKが`DownloadManager`で完了し、SHA-256検証後にインストールボタンへ変わる。
- ダウンロード中に設定画面を閉じても処理が継続する。
- 通信失敗・ダウンロード失敗後に再試行できる。
- API 35で提供元許可画面とパッケージインストーラーを開ける。
- 単体テスト、instrumentation、lint、debug/releaseビルド、公開物再取得検証が成功する。
- API 35でカテゴリ切替、サンプル反映、単位選択、`AT_MOST`保存、Room migration 2→3を確認する。
- API 35でREADのみのmanifest、権限状態、カレンダー選択保存、Calendar Providerからの予定取得、複数日予定、日別表示を確認する。

## 6. 非対象

Google Play配布、差分APK、バックグラウンドでの無断インストール、強制更新、Google Calendar APIによる直接同期、予定の追加・変更・削除、AI、Health Connectは実装しない。
