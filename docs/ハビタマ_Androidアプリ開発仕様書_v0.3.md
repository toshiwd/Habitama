# ハビタマ Androidアプリ 開発仕様書 v0.3

- 更新日: 2026-08-10
- アプリ版: 0.2.0（versionCode 2）
- 対象: Android / Kotlin / Jetpack Compose

## 1. 体験の中心

ハビタマは、毎日の小さな行動を報告すると「ハビタマ」と5つの力が育つローカル習慣アプリである。達成・未達の二択にはせず、できた分をポイントへ変える。未報告日や再開を罰しない。

## 2. v0.2で実装する範囲

- 初回に1〜3件の行動テンプレートを選択
- 最大3件の有効な行動と、カスタム行動の追加
- 3件を1画面で入力する「今日の報告」
- 部分達成、100%達成、120%上限の超過ポイント
- 体力・知能・美しさ・規律・回復力の累積値
- 今日の成長サマリー、累積ポイント、レベル表示
- 月間カレンダーと直近7日の記録
- 行動編集の翌日適用、過去スナップショット維持
- Room v1からv2への非破壊マイグレーション
- 署名済みAPKのGitHub Release配布

実装しないものは、年次の世代交代、キャラクターアニメーション、通知、Health Connect、AI、ログイン、クラウド同期、過去日入力、アプリ内更新確認である。

## 3. 画面遷移

1. 初回設定: 3テンプレートから1〜3件を選ぶ。
2. ホーム: 今日の各行動、達成率、5ステータス概要を表示する。
3. 今日の報告: 各行動の実績を数値・スライダー・増減ボタンで入力する。
4. 今日の成長: 行動別の成長ポイントと累積ポイントを表示する。
5. 記録: 当月カレンダーと最近7日の件数・ポイントを表示する。
6. 成長: ハビタマレベルと5ステータスの内訳を表示する。
7. 行動設定: 新規追加は当日、既存行動の変更は翌日から適用する。

ホーム・記録・成長は下部ナビゲーションで移動する。操作領域は48dp以上とし、システム文字サイズへ追従する。

## 4. デザイン契約

- 温かいアイボリーの背景、白い紙面カード、ティールの主要操作を使う。
- 植物は低コントラストの背景装飾とし、情報の可読性を妨げない。
- 行動は絵文字、円形進捗、実数値を併記し、色だけで状態を伝えない。
- 未報告は「記録なし」と表示する。失敗、連続切れ、罰の演出を使わない。
- 参照画像は雰囲気と情報構造の参考に留め、他作品固有のキャラクター、背景、ロゴは使用しない。

## 5. データ契約

`GoalEntity`は有効期間に加えて`slotIndex`、`growthType`、`icon`を持つ。1日にはslot 0〜2の最大3件が有効になる。

`DailyGoalRecordEntity`の主キーは`(date, goalId)`であり、目標スナップショットと評価結果を保持する。同日更新は同じ複合主キーをupsertする。

`GrowthStatsEntity`は5ステータスと累積値を保持する。同日再報告では、新ポイントと旧ポイントの差分だけを対象ステータスへ反映し、二重加算しない。全体の表示累積値は日次レコードの`energyEarned`合計を正とする。

Room v1→v2では、既存の1目標をslot 0・規律として引き継ぎ、日次主キーを複合主キーへ変換する。既存ポイントは規律へ移す。

## 6. 計算と入力

計算式はv0.2仕様を維持する。実績は`0..999999999`、目標は`1..999999999`の整数とする。表示達成率は無制限、評価値は1.2、行動1件の日次ポイントは12で上限とする。日付は端末タイムゾーンのISOローカル日付で、入力できるのは今日だけである。

## 7. 受入条件

- 初回に3行動を選び、ホームに3枚表示できる。
- 3行動を一括報告し、各行動の記録と成長タイプ別ポイントが保存される。
- 同日の再報告でレコード数が増えず、ステータスは差分だけ変わる。
- v0.1データをv0.2へ移行して目標・記録・累積値が残る。
- 目標変更後も当日目標と過去スナップショットが変わらない。
- カレンダーの未報告日は罰する表現にならない。
- 単体、Room、migration、Compose UI、lint、debug/releaseビルドが成功する。
- API 35エミュレーターで初回設定、報告、結果、3タブ、再起動保存を確認する。
- 公開APKのSHA-256と署名証明書がローカル成果物に一致する。
